## Readings (where the spec and the contract are silent)

1. **Window labels.** decisions files carry `window = w1 / w2`; stats, trades, positions, ledger carry `full / r3` (as T14). Compared as carried.
2. **W2 calendar and END** as T14 (D17 dates of the extended published NAV, END = last D03 row 2026-10-30; SCMO_0007 409 decisions). T15.md's W2 counts (IN 201, OUT-BUY 163, OUT-SELL 46, k and B counts) are checked for the three books that start 2019-01-02; for SCMO_0007 only the weeks (409) against the text, the rest against `step_1_spell_counts.json`, which carries per-book values.
3. **Index lines.** Fill = (O+H+L+C)/4 of the index's own bar; close marks; a session with no bar carries the last close (taken from the whole series on or before the date); a trade leg on a session with no bar raises (a failure). A bar with a missing price is refused. The first session must have a bar.
4. **V3 tie** tolerance 1e-9 relative (observed 0.0). A label date with no bar is a failure. For W2 the labels before 2019-01-01 read D25 (read from 2018-12-01), later ones D25c.
5. **`-idx` trade trigger and kinds.** Key = (IN) / (OUT-BUY) / (OUT-SELL, B); a trade is due on the session after decision j (1 <= j <= D-2) iff the key differs from j-1's. Kinds: `regime_in` / `regime_out` when OUT-SELL membership changes; `index_set_change` with OUT-SELL on both sides and a different B; otherwise `switch_in` / `switch_out` (IN <-> OUT-BUY). Also re-derived directly from the decision columns (C-v5-idx), not through the simulator.
6. **R4**: on the decisions of OUT-SELL spell n (full window), B and k are taken as empty for the two `-idx` rules (cash 1), so trades are keyed on the changed B; entries and exits of the spell still trade.
7. **R5**: the index bars are adjusted first (OHLC4 and close of calendar position i times (1 - 0.005/252)^i) and the last adjusted close is then carried over a session with no bar. The alternative (carry the raw close, then multiply by the factor of the carried-to session) was run: it differs by up to 1.1 index points on a no-bar session, but no `-idx` rule holds an index on 2020-02-01, 2025-02-01 or 2026-02-01, so both readings give the evidence's R5 NAVs to 4e-16. Unobservable in these data; **not** AFFECTS STEP 2.
8. **Constant mix (`cmix_<rule>`)**: target = the rule's mean shares over the weekly decisions (parent, GOLDBEES, cash, each index); initial position = that mix at T0's close; rebalanced fully (every line) on the session after every decision but the last, and fully at every basket change (e > 0), 20.8 bps only. Compared: params (1e-12), NAV, stats (incl. trade counts: `mix_rebalance` plus `basket_change` trades).
9. **Trade-record target shares** (`e_after`, `gold_share`, `cash_share`, `w_<index>`): the state's target after the trade. A basket change records the state in force (hold_parent: 1, 0, 0; the D1 trade of `-half`: 0.5, 0.5, 0). The D1 trade's `traded` is the stock lines only, V is the whole book, as T14.
10. **Ledger.** Spell row: B and k of its first stretch, `stretch_no` 0; stretch rows: maximal runs of the same B inside the spell, numbered from 1; `entered_from` / `exited_to` = the regime of the decision before / after the span ("start", "window end"); a = session on which the span's first decision is traded (0 for decision 0), b = session on which the ending decision is traded, the last session when the span reaches the end or the ending decision is the last decision; returns at closes, rules at 20.8 bps NAV. The engine's file has only `full` rows (T15's contract does not promise R3 rows); the verifier derives R3 rows too and compares them only if present.
11. **positions.csv**: rows with zero units are ignored on both sides; the files hold units after each trade at 20.8 bps; the stretch before a rule's first trade has no position row, so units x closes are compared from the first trade (the stretch before it is covered by C-nav).
12. **V4(a)** compares my six rules and hold_parent at 0 / 20.8 / 50 against T14's stored `daily_nav.csv` (relative 1e-12), `trades.csv` (date, kind, idx, e_after, V, traded, cost, stock / gold / cash before and after, nav_close_after, dec_j, basket in force; `gw_after` is T14-only and not compared) and `decisions.csv` (signs, labels, g, regime, e and gw of the six rules, exact). **V4(b)**: every index OHLC4 and close replaced by the cash level, cost 0, both `-idx` rules vs `-liq`, every session, 1e-12. **V4(c)**: sessions strictly before the first session on which any index line is traded into, 20.8 bps, 1e-12; done on my runs and on the evidence's own NAVs and trades. **V4(d)** cannot be re-done: C-engine-files reads `regression.json` -> `d_shared_code` (no unexpected change, none required-but-not-identical; the engine lists 21 expected changes) and says so.
13. **V5 units.** `positions.csv` units held constant between trades, times my closes, must reproduce the evidence NAV on every session from the rule's first trade (33,248 W1 / 60,300 W2 session NAVs); no `IDX_` row outside the `-idx` rules or outside OUT-SELL; in `-idx` OUT-SELL no GOLDBEES, no stock, index set = B (B from my decisions at the trade's decision j).
14. **Tolerances**: decisions and targets exact; NAV, stats, trades, ledger 1e-9 relative; T14 regression, identities, V4(b)(c) 1e-12.
15. **Frozen numbers.** T15.md section 2's own counts are an oracle beside Step 1's file (both windows, R3: OUT-SELL weeks, index weeks, k0 / k1 / k2, trades per rule).

## Findings and things that surprised me

1. **inputs.csv is not per window. AFFECTS STEP 2 (the engine's `inputs.csv` writer).** The smoke `w2/inputs.csv` lists only the four `published_nav` files; `w1/inputs.csv` (44 rows) carries the union of everything either window read (the W1 files, then D24, D12, D25c, the published NAVs). The union covers every file either rebuild reads, so C-data passes (every file read is listed, APPROVED, sha256-matching, covering, unrestricted), but a reader of `w2/inputs.csv` alone sees 4 of the 39 files W2 needs (D25, the Masters, D18, D17...), and the V1 text says the engine "writes `inputs.csv` from those rows" per window. The informational check C-inputs-per-window (gate = no) reports it: W1 0 of 37 missing, W2 35 of 39 missing. The engine should write each window's own file list (or the contract should say it is the run's union); I did not widen anything. D25 (pre-2019) is read by W2 only for the V3 tie of the Master labels dated before 2019-01-01 (T0's decision reads 2018-12-28), as the spec says.
2. The engine and the verifier agree to rounding on everything, including the R5 and R4 variants, the ledger and the cmix runs; I looked for a place the verifier could be vacuous: the shifted-index corruption changes 11,579 / 20,965 NAV rows and 234 / 294 trades, the isolated corruptions each fire only their own check, and the V5 units check rebuilds 33,248 / 60,300 NAVs from positions.csv alone.
3. `regime_ledger.csv` has no R3 rows (the contract says "per OUT-SELL spell" without a window; T15.md's R3 table needs the R3 spells only through stats and decisions). Step 4 should not expect them.
4. W1's T0 decision (2014-09-01) reads Master rows dated 2014-08-28, so the V3 tie needs index prices from before T0; the verifier reads D25 from 2014-08-01 (Smallcap 100 is far past its 2011-10-03 restriction).
