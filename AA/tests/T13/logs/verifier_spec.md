# T13 independent verifier: the deltas against T11's (gate V1)

Written 2026-11-18 by the Step 3 agent. The verifier is `AA/analysis/verify_t13.py`, a fork of `analysis/verify_t11.py`. **Everything in `tests/T11/logs/verifier_spec.md` holds unless it is listed here.** Sources: `T13.md` §1–§3 (frozen), `logs/evidence_contract.md` (T13's deltas), `tests/T11/logs/evidence_contract.md`, `tests/T11/logs/verifier_spec.md`, `tests/T11/logs/step_3_log.md`, `analysis/verify_t11.py`, and the evidence folders as files to compare against. The verifier imports only numpy, pandas, scipy (lazily, for one chi-square p-value) and the standard library. It never opened, read, grepped or imported `t13_engine.py`, `t11_engine.py`, `approved_data.py` or any other `analysis/` module. It parses `data/APPROVED_DATA.md` itself, as verify_t11 does.

Run: `python analysis/verify_t13.py --run smoke --draws 20` (or `--run headline`; `--evidence DIR --draws N --out FILE` for another folder; `--no-selftest` skips the corrupted copy). It writes `evidence/<run>/verify_t13.json`. The schema is verify_t11.json's (`exit_ok`, `gate_compared`, `gate_failures_and_missing`, `n_checks`, `checks`, `criteria` A1..C4 per book with `percentiles`, `companion` and `passes`, `percentiles` for every row group, `selftest.detected`, `selftest.detected_by`, ...) plus one new top-level key, `t13`: `entry_rule`, `seeds`, `n_buy` (weeks by n_buy per book and window, the 2-of-3-only and all-3-only weeks, all-3 invested weeks), `rule_all3` (the all-3 series' structure), `v4_a1_verifier_vs_t11_stored_worst_rel_by_run` and `prereg_sha256`.

## 2. Re-derivation (changes)

- **Decision rule.** At each decision date the latest Master row on or before it is read for the three indices (as T11). `n_buy` = number of BUY among the three SIGNs; `at_least_two_buy` = `n_buy >= 2`; `all_three_buy` = `n_buy == 3`; **`state` = 1 iff `n_buy >= 2`** (the rule); `state_all3` = 1 iff `n_buy == 3` (T11's rule, the comparator). Spells, bounds, draws, trades, sleeve trades, `sessions_invested`, the constant-mix f, R2, R3, R6 and R7 come from `state` (2-of-3).
- **Seeds:** `[16, 3, id]`, `[16, 6, id]`, `[16, 11, 3, id]`, `[16, 11, 6, id]`. The verifier's own sample-of-draws seed and sampler self-test seed are `20261118` (T11's verifier used 20261117; neither is a test seed).
- **New runs:** `strategy_all3` (timed sleeve) and `strategy_all3_fixed50` (50/50) at 0 / 20.8 / 50 bps, full window, LBES cash: the same simulator with `state` replaced by `state_all3`. Their `invested_weeks` is the number of all-3 IN weeks (93).
- **V4(a2)** (the D17-calendar regression against T08's and T06's stored 2019 NAVs and decisions) runs on the **all-3** state, because those stored runs are all-3 runs.

## 4. Self-test (changed)

T11's nine corruptions plus three, all on one copy, each of which must be caught by its own check: an `n_buy` cell changed (row 33; C-dec-nbuy), a `state_all3` cell flipped (row 77; C-dec-all3), and one `strategy_all3` NAV row at 20.8 bps × 1.001 (the 501st session of the first book; C-all3). The new checks are built so that no other corruption reaches them (C-dec-nbuy and C-dec-all3 never read `state`; C-dec never reads `n_buy` or `state_all3`; C-comparators-r7 no longer reads the all-3 runs), so "detected by its own check" is attributable.

V4(c) (the AST comparison with `t11_engine.py`) is still the engine's own gate; the verifier only reads its record. `audit.json` `readings` (E25 and the reworded E3, E18, E21) are text and are not checked. ## 6. Readings (in addition to T11's spec §6, which all stand, including the week-0 `sessions_invested` reading)

1. **"Detected by its own check".** To make the two new decision corruptions attributable, T11's single C-dec is split into three checks (C-dec: the 2-of-3 state; C-dec-nbuy: n_buy and its booleans; C-dec-all3: the all-3 state). The rule "no week IN under all-3 and OUT under 2-of-3" is checked in C-dec from the evidence's own sign columns.
2. **The all-3 series' sleeve trades = 9** is T11's number (T11.md §2, T11's step 3 log); T13.md §2 confirms it indirectly ("T11's list without 2015-01-23").
3. **The contract's smoke trade counts (§5)** are counts of the real rule in SCMO_0003, not of the smoke run as such, so the verifier asserts them whenever SCMO_0003 is in the evidence (the headline included).
4. **V4(a1) on the evidence and on the verifier.** The contract has the engine compare its all-3 runs with T11's stored file. The verifier does it twice: its own NAVs against T11's stored file (C-regress-t11) and the engine's all-3 NAVs against T11's stored file (C-all3), both at 1e-12, for every book in the evidence (one in the smoke run).
5. **r3 weeks by n_buy** (78 / 31 / 16 / 85) are in `step_1_spell_counts.json`, not in T13.md, and are compared with that file only.
