# T09 Step 3 log: the independent verifier (2026-11-12)

## What was built
`AA/analysis/verify_t09.py` (about 1,900 lines), forked from `verify_t08.py` (read as a model, not imported), written from `logs/verifier_spec.md`, `T09.md` §1-§3 plus its amendment block, `PLAN.md` / `PLAN_v2.md` and `logs/evidence_contract.md`. Imports: numpy, pandas, scipy (one chi-square p-value), the standard library. It parses `data/APPROVED_DATA.md` itself (status, id, path, through-date, sha256 prefix, `[usable-from: d]` marker) and opens a file only through `rd()`, which refuses a non-APPROVED row and, for a restricted row, refuses a first read date earlier than its marker (standing rule 7). The Smallcap 100 price file is read as text and only lines dated 2011-11-25 or later are parsed; the Smallcap 100 Master xlsx cannot be read as text, so it is parsed whole and rows before 2011-11-25 are dropped on load, before any use (the engine does the same, its reading E3).

I did not open `t09_engine.py` or `t08_engine.py`, nor any engine source. I read `audit.json` `readings` only after the verifier was finished and validated on the mock sets and on the smoke evidence; they agree with my readings (E1-E21 against the list below; no conflict).

Usage (from `AA/`): `python analysis/verify_t09.py` (headline evidence, 2,000 draws, all four books, plus the self-test); `--run smoke` (20 draws, books found in the evidence); `--evidence DIR --draws N --books ...`; `--no-selftest`; `--out FILE`. Writes `verify_t09.json` beside the evidence. Exit 0 only if rows were compared, no gate check failed or is missing, no expected evidence file is missing and, in the default run, every corruption of the self-test is detected by its own check.

## What it re-derives (all from the raw files)
Calendar (D26), index closes and OHLC4 fills (D25), decisions (three Master files, as-of, stale-row rule) and the MAUc1 gold signal (D24b Master, cross-checked to the weekly csv), the GOLDBEES chain (D09b then D09, T03's de-spike on D24b's daily range, raw fill on the 3 sessions without an MCX bar, previous close and fill on 2016-10-30), cash as-of (LBES, LIQUIDCASE), the simulator with the T06/T08 `trade()` arithmetic, quarterly resets, sleeve rebalances, and these runs at 0 / 20.8 / 50 bps: strategy, strategy_fixed50, hold_proxy, constant_mix, constant_mix_timed, sleeve_only, sleeve_only_timed, index_Nifty100/MC100/SC100; at 20.8: R7a, R7b, the rule on LIQUIDCASE cash and on the R3 window (timed and 50/50). Closed form for the strategy NAV (product over fixed-unit segments). Spells, bounds (`lo = min(2, shortest)`, `hi = longest`), tuple counts by inclusion-exclusion and by a plain DP, the four samplers regenerated from their seeds for every saved draw, the exactness test of the sampler (19-tuple chi-square, own seed; position means within 4 SE), percentiles twice (vectorised and loop), a sample of 40 draws per group (first 20 + 20 seeded random) re-simulated at the group's cost (all nine statistics, 1e-9) and, for F1 and F3 at 20.8, 40 curves against the float32 file (1e-5).

C-data, C-sc100-restriction, C-dec, C-pit, C-nav0, C-nav0-closed-form, C-cost, C-stats-all, C-comp, C-trades, C-proxy-units, C-positions, C-sleeve, C-sleeve-identity, C-reset (reset values and identities), C-gold, C-real-states, C-v4-identities, C-v4-splice, C-states-struct, C-states-lengths, C-gold-states, C-states-csv, C-states-sessions, C-signatures (info), C-draws-coverage, C-n49-regen, C-n410-regen, C-draw-nav, C-count, C-spells-step1, C-support, C-sampler, C-percentile, C-percentile-log (info), C-engine-files. The self-test applies nine corruptions to a copy of the evidence: five decisions flipped (C-dec), a NAV column x 1.001 (C-nav0), an N4.10 in-or-out draw out of bounds (C-states-lengths), an N4.10-g gold draw out of bounds (C-gold-states), three gold weeks flipped (C-gold), a sleeve rebalance removed (C-sleeve), a quarterly reset removed (C-reset), the Smallcap 100 `usable_from` lowered in `inputs.csv` (C-data), an F3 draw's end NAV x 1.001 (C-draw-nav).

## Disagreements between verifier and engine evidence
None on any number. Two format deviations from `logs/evidence_contract.md`, both handled as readings and noted in `verify_t09.json`, not failures:
1. `count_table.json` `bounds` for window `r3` is flat (`{"in": .., "out": .., "buy": .., "sell": ..}`), not nested under `io` / `gold` as the contract says for both windows. The values are correct.
2. `daily_nav.csv` and `trades.csv` hold no rows for the two R7 runs (`strategy_r7a_proxy_fill_at_close`, `strategy_r7b_gold_weight_50_before_2014-07-01`), which the contract lists among the run values; `stats.csv` holds them and every statistic and the trade count were compared (C-stats-all). If Step 4 wants R7 curves, the engine must write them.

## Readings I chose where the spec is silent (flagged)
1. Books: default all four; for a smoke run, those found in `decisions.csv`; draws per group default 2,000, 20 for a smoke run.
2. `through` rule: every file must cover END (2019-01-02) except D09b, which ends 2014-06-30 by design (D09 takes over); the literal V1 text ("a through-date that covers the window") would fail D09b.
3. A file the verifier needs to rebuild the run but `inputs.csv` does not list is a failure; a listed file the verifier did not read is a note. The `usable_from` column of `inputs.csv` must equal the registry's marker (empty where none); this is what the lowered-marker corruption breaks.
4. `trades.csv`: every run is compared (switch, sleeve rebalance, quarterly reset, mix rebalance) on `idx, date, kind, e_after, V, traded, cost, nav_close_after` at 1e-9; `gw_after` only on trades that leave the book OUT (what an IN trade carries is undefined; empty for hold and index runs).
5. `sleeve_trades.csv`: exits (`switch_out`) and rebalances; before-values and `g_before` compared on rebalances only; `g_*` read as BUY/SELL or 1/0; `gold_fill_proxy_period` must be exactly "session before 2014-07-01"; an exit's sleeve value must equal V - cost from `trades.csv`.
6. `quarterly_resets.csv` columns found by prefix (`value_before_*`, `value_after_*`, the index name as suffix); identities on the file's own numbers: cost = traded x bps/2/1e4, values before sum to V, values after = weights x (V - cost) to 1e-12 of V, traded = sum |target - held|, continuity at 0 cost.
7. `sleeve_trades` (stats and draws) counts `sleeve_rebalance` trades only; `quarterly_resets` counts `quarterly_reset` trades; in stats.csv `invested_weeks` is compared on the rule's rows (strategy*, R7) only.
8. `spell_sig` equals `strategy_sig` on F2 rows and `g_spell_sig` equals `real_g_spell_sig` on F4 rows (informational; they agreed).
9. V4: (a) one-index book at weight 1, 0 cost, no resets equals close / first close to 1e-12 for the verifier's own simulation and for the engine's `index_*` NAVs; (b) hold-the-proxy at 0 cost against a plain day-by-day loop (1e-12 mine, 1e-9 the engine's); (c) the shared-code AST comparison with `t08_engine.py` is not repeated (I may not read it); I check the shared arithmetic instead through the sleeve and reset identities and the T06 `trade()` re-implementation; the engine's own `regression.json` and `audit.json` gates are read only for a `false`; (d) signals through C-dec / C-gold; (e) splice day return equals MAUc1's own, MAUc1 rows consecutive over the proxy's dates, proxy returns equal MAUc1's, no non-positive price, the sessions without an own gold bar are exactly 2016-10-30 and without an MCX range exactly 2014-10-23, 2015-01-01, 2015-11-11.
10. Counts of the real series from the data (flips on an exit, while IN including the entry decision, flip dates while OUT, gold spells with an OUT week, quarter starts 29 / 28) are compared with `step_1_spell_counts.json` for both windows; seeds are compared with its `seeds` block.
11. The `analysis.log` percentile check (C-percentile-log) is informational and does nothing until Step 4 writes the log.
