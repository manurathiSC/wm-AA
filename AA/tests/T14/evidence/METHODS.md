# T14 methods (evidence/report.html and evidence/headline/)

Test T14: the three-index switch of T06/T08/T11 with a different holding in the OUT-SELL regime (switch OUT and MAUc1 gold signal SELL): half parent + half GOLDBEES (`-half`) or the liquid ETF alone (`-liq`), on the 50/50 and the 80/20 base sleeves, on W1 = 2014-09-01 -> 2019-01-02 (T11's inputs) and W2 = 2019-01-02 -> 2026-10-30 (T08's inputs). The frozen design is `../T14.md` sections 1-3 (sha256 `99fe0f3a...`, `python tests/T14/check_prereg.py`); this file only says how the evidence and the page were made.

**Data.** Only APPROVED rows of `AA/data/APPROVED_DATA.md`, opened through `analysis/approved_data.py` (engine) or the verifier's own parser; the files and sha256 prefixes of each window are in `headline/{w1,w2}/inputs.csv`. Each window uses the inputs of the test it extends (T14.md section 3 table). Contaminants: T14.md section 3 (rebuilt 2014-2018 parent with no published series, nine manual Eikon exports in W1, price returns only, unrecorded cash-file source, raw GOLDBEES OHLC4 after 2026-09-28 in W2).

**Engine.** `analysis/t14_engine.py`, a fork of `t11_engine.py` (25 functions copied verbatim and AST-checked by V4(d)) with T08's W2 paths. Per window and book it runs the six rules (`50-orig`, `50-half`, `50-liq`, `80-orig`, `80-half`, `80-liq`) at 0, 20.8 and 50 bps, the comparators, the nulls F1 to F5 on 2,000 draws regenerated from T11's (W1) and T08's (W2) seeds, and the R2 (LIQUIDCASE cash) and R3 (own window) cells. A parent rebalance inside the `-half` regime re-weights only the parent half at its current value (decision D1). Its console output is `../logs/step_5_run_w{1,2}.log`; `headline/{w}/audit.json` holds every gate, count and reading.

**Gates.** V1 independent verifier `analysis/verify_t14.py` (written by a different agent from `../logs/verifier_spec.md`, never opened the engine; `headline/{w}/verify_t14.json`: 15,351,589 and 15,570,927 comparisons, 0 failures, 15 planted corruptions detected); V2 point in time; V3 nulls hold their tables and equal the stored T11 / T08 draw states; V4 regression (the `-orig` rules reproduce the stored T11, T08 and T06 NAVs to 2.2e-16 and their stored draw rows), identities, shared code, signals, G0 / seam; V5 samplers; V6 trade and cost identities including the half-regime entry, the partial basket trade and the liquid-only regime. `analyse.py` refuses to print a result if any gate failed.

**Analysis.** `analyse.py` reads only the evidence and writes `analysis.log` (percentile = (draws worse + 0.5 ties) / draws x 100, p = (1 + draws at least as good) / (draws + 1), MDE = 2.8 x null SD, Holm over the window's 16 criteria per book, D-table, regime ledger, R6 paired contrast, R1-R7, the outcome map applied mechanically). `fill_writeup.py` writes section 4 of `../T14.md` (sections 1-3 byte-identical), `report.py` writes `report.html` (every number carries a provenance key), `check_page.py` re-derives every number from the evidence with its own code (13,444 checks, 0 failures at the time of writing).

**Readings and choices not in the frozen text:** `../logs/step_2_log.md` (engine), `step_3_log.md` (verifier: its own reading of the W2 R2 cash chain was corrected after a 1e-9 mismatch), `step_4_log.md` (scripts, 21 readings). Curves of 40 draw ids per null are stored (the first 20 and 20 from `default_rng([17, 1])`), not all 2,000.

**Reproduce.** `bash tests/T14/run.sh` from `AA/` (about an hour). `draws.csv` (about 285 MB per window) is not in git.
