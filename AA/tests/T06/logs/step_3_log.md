## Readings chosen where the spec / T06.md section 3 is silent (most literal reading; the engine was not consulted)
1. **C-data through-date (coordinator's clarification, 2026-11-06, applied as written):** rows D19 (weight matrices, columns, weight sources) and D05 (rebalance history) are exempt from "Through covers END" (their through-dates, 2026-09-10 / 2026-09-16, are the newest baskets by design and the last basket stays in force to the window's end); they are still checked as APPROVED rows with a matching sha256 prefix. D12 (MCX de-spike range, through 2026-09-28; later GOLDBEES fills use the raw OHLC4) is exempt likewise. D17, D18, D03, D09, D11 must cover END (2026-10-22, derived from D17's last date). "n/a" rows pass the through test.
2. C-data also checks the files the verifier itself read (approved, sha prefix against the disk, through) and that each `inputs.csv` row's sha256 equals the file on disk and its `through` equals the APPROVED row's string. A file the verifier read that is absent from `inputs.csv` is a note, not a failure (the spec asks only that listed files be approved). `inputs.csv` path separators may be `\` or `/`.
3. END = last date of D17 per book (2026-10-22 in all four books). A window with a session beyond the cash file's last date is an assertion error (no accrual), as is a missing LIQUIDCASE level.
4. Live window: T0 = first D17 session on or after 2021-11-01 (2021-11-01 itself), decision dates = T0 then the last session of each later ISO week, to END; the view's NAV is 1.000 at the live T0 close, basket in force at that session; the first state is OUT so no initial stock position arises in the strategy or in any draw.
5. `decisions.csv`: compared on key (book, window, j); if the evidence has no `window` column (or no `live` rows) only the full window is compared and a note says so.
6. **`sessions_invested`:** the trade session of week j is decision session + 1; week j's coverage = decision_idx[j+1] - decision_idx[j] (the sessions from its trade session up to, not including, the next week's trade session), the last week (decided on the last session, never traded) covers 0; the first week is OUT in every draw, and so is the last, so the first/last-week conventions do not matter. Calibrated on T03: the rule gives 945 and its draw 445 gives 941 (the "differs by 4 of 1,884" of T06.md section 1); the other readings give 946/942 or 947/943 and so do not match "1,884".
7. **Secondary statistics** (the spec names them only in T06.md section 2): Ulcer index = sqrt(mean((100 * NAV/peak - 100)^2)) over all sessions; days at least 10% below the running peak = count of sessions with drawdown <= -10%; longest time under water = longest run of consecutive sessions with NAV < running peak; Calmar = CAGR / |max drawdown|. Calibrated on T03: all 56 stats rows of `tests/T03/evidence/headline/stats.csv` reproduced to 1e-15 (integers exactly).
8. **Constant mix:** f = invested weeks / weeks of the window, rebalanced at every decision's next session including after T0's decision (the literal reading; T03's verifier found it matches T03's engine), and at every basket change.
9. **Published comparator:** if `daily_nav.csv` has a run whose name contains "publish" (T03: `published_D17`, cost blank) it is compared with the published NAV rebased to 1.000 at T0, relative 1e-9.
10. **C-t03:** decisions on all shared (book, decision_date) rows: state, three signs, three labels, latest label, label age, session index, and trade date (not for T03's last decision of each book, which T03 did not trade). NAVs of strategy, hold_parent, sleeve_only at 0, 20.8, 50 bps, the published comparator, and the constant mix **simulated with T03's own f** (T03's invested/decisions; T06's f differs because the window is longer), up to and including 2026-08-07, relative 1e-12. Extra (not in the spec): strategy trades and positions on the overlap, relative 1e-10.
11. **C-draw-nav:** per book and type, ids 0..19 plus 20 seeded random ids from 20..1999 at each of 0 / 20.8 / 50 bps (full window, LBES), every statistic of the draws.csv row compared at 1e-9 (end NAV, CAGR, max DD, vol, Ulcer, days below 10%, longest under water, Calmar, sessions); for 20.8 bps the whole curve against `draw_curves_20.8.npz` (float32, 1e-5). Ten seeded draws (id 0 always included) per book and type for the LIQUIDCASE run and for the live window, 20.8 bps.
12. **Percentile target:** the rule's value comes from the verifier's own derivation (not the engine's stats.csv); C1 = CAGR (higher better), C2 = max drawdown (a shallower, i.e. larger, value is better). Percentiles are computed by two own implementations (vectorised, loop) and compared with each other. The spec's "compare with `analysis.log` and with the `stats` the analysis wrote" cannot be done mechanically because the log's format and the stats file are not specified: `C-percentile-log` (informational, non-gating) checks that each headline percentile appears as a number in `analysis.log` (looked for beside the evidence, one and two levels up); percentile columns in `stats.csv`, if any, are compared. **Open issue:** once `analyse.py` exists, a strict comparison of its percentile table should replace this.
13. **C-states:** HI_in, HI_out = the rule's longest in- and out-spell on the full window (derived), lower bound 2, used for both windows. Checked per draw: shape and dtype (uint8, 2,000 draws, the book's weeks), first and last state, spell counts, invested weeks, N4.9 sorted lengths, N4.10 bounds and sums; plus (extra) N4.9 states regenerated from `default_rng([3, id])` and compared with the saved states; draws.csv coverage (ids 0..1999 exactly once in each of the 10 groups per book: 3 costs + LIQUIDCASE + live, per type); the `invested_weeks`, `n_in_spells`, `n_out_spells`, `in_lengths`, `out_lengths`, `sessions_invested`, `sessions` columns against the states, for every row.
14. **C-sampler (extra):** over the saved N4.10 states the first and last in- and out-spell length have the exact mean of a uniform ordered tuple (computed with exact fractions from the inclusion-exclusion counts), within 5 standard errors.
15. **C-audit:** tolerant of key names: compares the keys it knows (t0, sessions, decisions, invested_weeks, in_spells, out_spells, round_trips, initial_basket_switch_session, skipped_baskets_dropped) if present in `audit.json` (under `books` or at top level), requires every `v2_*_checked` > 0 and every `v2_*after_decision*` / `*not_after*` = 0.
16. **C-count:** `count_table.json` is walked recursively (list or nested dict); an entry is any dict with `n_ways`, with book / window / state taken from its fields or from the enclosing keys; k, S, lo, hi and n_ways must all match. Also compared with `logs/step_1_spell_counts.json` (`feasibility`).
17. **Positions** (extra): strategy rows of `positions.csv` with non-zero units against the verifier's units after every trade (stocks, GOLDBEES, LBES).
18. **G0:** the verifier's own always-in and the engine's hold_parent 0-cost NAV are both tested within +-0.25 pp/yr overall and +-0.5 pp per calendar year (year returns from year-end values, the first year from 1.000). The overall gap is computed with session years ((sessions-1)/252, as section 3 step 9) and also with calendar years (days/365.25); both are gated. `g_engine.csv` is compared to the verifier's numbers at 1e-6 pp, accepting either year convention: the engine's value 0.04507 pp/yr for SCMO_0003 (the same as T03's) is the calendar-year gap, the session-year gap is 0.04619 (T03's own verifier printed 0.04619); the worst-year gaps agree exactly.
19. `count_table.json` may name k and S as `spells_k` and `weeks_S` (the smoke evidence does, inside a `tables` dict); both spellings are accepted.
20. C-draw-nav only samples ids that exist in the saved states (a short smoke run does not crash it; C-states-struct reports the wrong number of draws).
